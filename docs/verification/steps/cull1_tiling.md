# カリング Step 1：タイル分割＋視錐台カリング（スクロール版のみ）

実装: `src/scroll/tiling.js`（新規）、`src/scroll/scene.js`（build 後に tileScene を呼ぶ）、`src/scroll/app.js`（`?tiles=0` で分割なし）。動画版（index.html / src/main.js / src/scenes / src/lib）は無変更。

## 分割単位
- 山地メッシュ（'mountains'、約69万三角形）: 三角形の重心で xz 3,000 m 格子に分割 → 419 タイル。頂点バッファ共有、タイルごとに index と境界球・境界箱を算出。
- 静的 InstancedMesh（木・樹冠・街灯柱など、インスタンス2,000以上）: 各インスタンスの位置で xz 350 m 格子に分割。インスタンス属性（aBld / aPar / aTaper）もタイルぶんだけ切り出し、頂点属性・マテリアルは共有。境界球に 8 m の余裕。
- 分割しないもの: 動く車・歩行者・雪・光点（Points）、建物の箱（12,255 件）、2,000 件未満の小さなセット（切妻・タンク・テレビ塔など）。

## 継ぎ目の確認
タイルは同じ頂点・同じ行列を共有するだけなので幾何学的な継ぎ目は生じません。確認は基準画像との画素比較：縦（390×844）・横（960×540）× 9 地点 = 18 枚すべてで差分 0 px（最大チャネル差 0）。`?tiles=0` は基準と完全一致（再現性も確認）。

## 途中で出た差分と対処（失敗として記録）
最初の実装（箱も小セットも分割）では 15/18 枚に 6〜196 px の微小差分（最大チャネル差 50）が出ました。
- 原因の切り分け: 山地のみ分割 → 差分 0。境界球の余裕を 400 m にしても差分は変わらず → カリング欠けではない。
- 原因: 建物の箱・タンク・テレビ塔など「重なり合う（同一平面の）面」を持つバッチをタイルに分けると、タイル間の描画順が元のインスタンス順と変わり、深度が等しい面の勝敗（z-fighting）が入れ替わる。
- 対処: 箱（12,255）と 2,000 件未満のセットは分割しない。再撮影で全 18 枚差分 0。
- 代償: 箱 約15万三角形は常に描画される（下限が上がる）。
