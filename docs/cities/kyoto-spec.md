## 1. コンセプト
**晩秋の夕暮れから夜へ、灯りがともる古い街並みの低い目線。** 日没前の橙の空の下、鴨川の川面から入り、四条通を東へ。祇園の町家の格子に提灯がともり、朱の西楼門をくぐって東山の斜面へ。二年坂・三年坂の石畳の坂を登るうちに空は群青に落ち、ライトアップされた**紅葉の赤と橙**が闇に浮かぶ。最後は清水の舞台の高さまで上がり、**眼下に京都の夜景が広がり、遠くに白く立つ京都タワー**が見える。

### 札幌・仙台・東京との対比
| | 札幌 | 仙台 | 東京 | **京都** |
|---|---|---|---|---|
| 季節・気配 | 冬、静けさ、雪 | 盛夏、祭りのざわめき | 冬の夜、光の密度 | **晩秋、時間の厚み、紅葉と提灯** |
| 時間 | 昼 → 夕 | 夕方 → 夕景 | ブルーアワー → 夜 | **日没前 → 夜（点灯が進む）** |
| 色 | 白・青灰 | 緑・五色 | 紺、金、窓の暖白 | **群青の空、紅葉の赤・橙、提灯の暖橙、瓦の黒** |
| 動く要素 | 雪 | 吹き流し | LED のきらめき＋光跡 | **舞い散る紅葉＋提灯の揺らぎ** |
| 空間 | 広い抜け、塔が軸 | 並木・アーケードのトンネル | 高層の壁に挟まれた光の谷 | **低い町家の軒先と石畳の坂、登るにつれて開ける視界** |
| 主役 | 空と山、塔 | 通りと飾り | 光の密度と塔 | **紅葉と灯り、そして古い建築（朱の門・舞台・塔）** |
| フィナーレ | 塔まわりの周回上昇 | 青葉城址から俯瞰 | 金の線が塔へ導く | **清水の舞台の高さから京都の夜景と京都タワー** |

東京が「垂直の壁と密度」なら、京都は**「水平の低さと、登ることで開ける視界」**。カメラは通り・坂に沿って進み、最後に市街へ向き直る。縦に積む東京に対し、京都は**登る（標高が稼げる）**ことが体験の核になる。

## 3. 季節と時間帯の案
オーナーの好みは京都の夜景。コレクション共通の言語は「スクロールで時間が進む」こと。

### 推奨：晩秋（11 月下旬）× 日没前 15 分 → 夜
- **季節**：晩秋、紅葉のライトアップ。理由：(1) 実在の夜間特別拝観が今の時期（§0）で、根拠がある。(2) 札幌（冬）・東京（冬）と季節が被らず、仙台（盛夏）とも別。(3) 紅葉の赤・橙は、白（札幌）・緑（仙台）・金（東京）と**色で明確に対比**する。
- **時間の進行**（`timeline` と時刻トラック）：
  - p=0：日没の約 15 分前。西の空に橙、頭上は淡い青、東山は暗いシルエット。町の灯りはまだ少なく、提灯が点き始める。
  - p≈0.35：日没直後。ブルーアワー。町家の窓と提灯の灯りが優勢になり、空は群青へ。
  - p≈0.6：夜の始まり。紅葉のライトアップが画面の主役になる（地面からの暖色の照り返し）。
  - p=1.0：ほぼ夜。空は濃紺、京都の夜景の光が最大。
  - 「灯りがともっていく」過程が、そのままスクロールの進行になる（光点・提灯・ライトアップの点灯率をトラックで上げる。仙台と同じ仕組み）。
- 季節の代案（U-2）：
  - **春（桜と東山花灯路）**：3 月の東山花灯路はルートが A 案とほぼ同じ。ただし期間・実施内容は**未確認**。桜は花の塊の表現が必要で、紅葉より重い。色はピンクで札幌の夕景（ピンクの空）と被る。
  - **夏（祇園祭の宵山、鴨川の納涼床）**：仙台の盛夏・提灯の祭りと被る。
  - **冬の雪の京都**：札幌・東京と季節が被る。雪の古建築は魅力的だが雪の表現は札幌で使い済み。
- 空の方位の注意：A 案は**東へ進む**ので、前方（東）は暗い東山と群青の空、後方（西）に橙の残照。進行中は前を向くため、序盤の橙は「振り返る」構図や、建物の西面に当たる光、水面の反射で出す（§8 の方針）。

## 5. プロシージャル要素・ランドマーク・近接演出（A案）
### 5-1. 方針
- 共通 lib（createSky、BuildingBatch、createGlowPoints、createCars、createPedestrians、ground のストリップ配列、静的シャドウマップ、タイル分割）を**変更せずに**使う（ラップ・拡張のみ。U-11）。共通側で足りなければ実装前に報告して止まる。
- 紅葉の樹木は、仙台のケヤキで実装済みの**インスタンス単位の LOD＋視錐台カリング＋影ベイクは全木近景**の方式（`sendai/trees.js`）を踏襲する（コードは京都モジュール内に新規で書く）。
- 静的なものはタイル分割。動く CPU 更新のもの（車・歩行者）は除外。舞い散る紅葉・提灯の揺れ・水面のきらめきは**シェーダの時刻のみ**で動かす。

### 5-3. ランドマークの表現と近接演出の候補
- **八坂神社 西楼門**（Z2 の突き当たり）：朱の面積が初めて大きく出る場面。提灯の列が左右から収束。近接演出＝楼門の**下をくぐる**カメラ（高さ 8〜10 m、門の内側の暗がりから境内の明るさへ）。門の内側が暗がり→開ける、の対比で、見え方が変わる。
- **ねねの道・二年坂・三年坂**（Z3〜Z4）：石畳に町家の灯りと提灯の**光だまり**が落ちる。近接演出＝坂の中心線を低く進み、**頭上に軒の連なり**。振り返り（180°近いパン）で**八坂の塔が坂の上に立つ**（Z4 中盤の見せ場。縦画面では縦構図が特に有利）。
- **清水寺**（Z5）：仁王門→三重塔→本堂の順。近接演出＝**舞台の床の高さから懸造りの柱を見下ろす**、舞台の手すり越しに**紅葉の谷**（赤の面積が最大）を見下ろす、舞台の外へ踏み出して上昇、のシーケンス。
- **フィナーレ**：舞台より高い視点（30〜60 m）から、紅葉の谷越しに市街。**京都の夜景（低い屋根の海の灯り）**、遠くに**京都タワー**（南西〜西の方向、小さく白く）。実際の位置関係（舞台は南西向き）が構図に合うかは U-12 で確認。
- ライトアップの表現：紅葉は**下から暖色に照らされる**（ファサードの「空の映り込み」ではなく、木の下面に暖色の乗算＋近傍の光点によるグロー）。実在の演出の再現ではなく、一般的な夜間ライトアップの表現（U-7）。

### 5-4. 路面・水面の扱い
- **実反射（鏡像の再レンダー）は使わない**。
- 石畳：ground シェーダのストリップ配列に、**提灯・町家の灯りから作る柔らかな光だまり**を加える（東京の路面グロー方式の流用。京都モジュール内で実装）。乾いた石畳で、鏡面にはしない（U-14）。
- 鴨川：暗い水面に**上下反転したグロー帯**（先斗町・南座・橋の灯りを水面で反転）。流れの**ゆるい筋**をシェーダの時刻で動かす。三角形 〜10k。
- 窓・瓦の反射は既存のファサードシェーダの空の映り込みで扱う。

### 5-5. 点数の注意（跳ねやすい要素）
- **遠景の灯り**：盆地の夜景は広大で、点数が増えやすい（〜120k）。タイル分割で視野内のみ、LOD 距離で間引く。画面に同時に出る光点は **〜200k 以下**を上限にする。
- **提灯・町家の窓**：祇園・坂は密度が高いが近景の数は限られる（視野内 〜30k）。
- **町家の数**：3,200＋簡略 6,000。超える場合は簡略を点・塊に置換。

## 6. 「動く環境要素」の方針
札幌＝雪、仙台＝吹き流し、東京＝LED のきらめきに相当する、京都の「環境の動き」を提案する。

### 主：舞い散る紅葉
- **何**: 風に舞い、ゆっくり落ちる紅葉の葉（赤・橙・黄）。境内・坂・清水の谷で特に多く、一枚ずつ回転しながら横へ流れる。
- **方式**: 札幌の雪（Points）と同系の**シェーダ駆動の粒子**。位置は `fract` と時刻 `ambientT` から決定的に計算。葉の色は個体ごと（`aHue`）、大きさを数段階、風の揺れ（横の正弦）と回転（フラグメントで楕円の向きを回す）。**CPU 更新なし**。カメラ周辺の箱の中で循環（雪と同じ）。ライトアップ領域では葉が明るく見える（暖色の乗算）。
- **契約上の置き場**: `ambient: { name: '紅葉', counts: { normal, light } }`。`counts` は粒子数（仮置き：normal 12,000／light 5,000）。`setAmbientCount(n)` は粒子数を変える。
- **霞**: Points なので共通の霞は効かない（札幌・東京と同様）。実装時に東京の `_hazePoints()` 相当を京都モジュール内に持つ（共通コードは変えない）。

### 副：提灯の揺らぎと光のちらつき
- 提灯・行灯の光点を、時刻と位相で**ごくゆるく明滅**（振幅 〜8%。祇園の灯りの息づかい）。CPU 更新なし。
- 鴨川の水面の筋と反転グローのゆらぎ（Z1）。

### 補助（軽微）
- 遠景の街灯りの**まばらな瞬き**（盆地の夜景）。
- 人力車・歩行者は既存の更新で動く。
- 雪は降らせない。

## 8. カメラ方針
共通: 7 秒、p→t の写像（p=0.94 で終了し以降は最終構図を保持）、横／縦の混合（アスペクト 0.88〜1.12）は共通仕様どおり。横は進行度キーフレーム（`kt(p)`、仙台・東京の `camera.js` と同じ作り）、縦は `PathRig`（`dollyKeys`）。**カメラの near は 4 m**（`CAMERA_NEAR`）なので、紅葉の枝・町家の軒・楼門・舞台の柱に近づくときは**距離 4 m 未満に入らない**キーにする（仙台の樹冠、東京の壁の失敗の再発防止。坂は幅 3〜5 m なので、**中心線を通り、両側の軒が 4 m 未満にならない幅を確保**する。実寸の坂の幅が狭ければ、圧縮配置で少し広げる）。
### 横画面（16:9 など）
- **Z1**：鴨川の上 30〜40 m から東を向いて入る。川面の橋の灯りと両岸、正面に暗い東山。FOV 38〜40。橋の高さへ降りる。
- **Z2**：目線 6〜8 m で四条通を東へ。町家の軒と提灯が左右を縁取り、消失点に八坂神社の朱の楼門。FOV 34〜36。花見小路の交差で一度横へ視線を振る。
- **Z3**：楼門をくぐる（8〜10 m）。境内で上昇して視界を開き、紅葉の赤を初めて大きく見せる。ねねの道へ。FOV 32〜36。
- **Z4**：二年坂・三年坂の坂道を、低い目線（4〜6 m）で登る。被写界深度は近景の軒をぼかし、坂の先に合焦。中盤で**振り返り**、八坂の塔を坂の上に。FOV 30〜34。
- **Z5**：仁王門・三重塔を見上げ、舞台へ。舞台の手すり越しに紅葉の谷を見下ろす。最後に舞台から外へ出て 30〜60 m まで上昇、市街と京都タワーを視野に。最終構図（p=0.94〜1.0 保持）：**画面下に紅葉の谷と舞台の屋根、中央に京都の夜景（低い屋根の海）、奥（やや左）に京都タワー、空は濃紺**。
### 縦画面（9:16 など）
- 仙台・東京と同じく**経路に沿った PathRig**（FOV 55〜62、上限 65）。縦長の画面は「坂の上の八坂の塔」「舞台の高さ」を縦に使える。
- Z2〜Z4 は通り・坂の中心線を画面中央に保って前進。Z4 の振り返りは縦画面でこそ強い（坂と塔が一本の縦線）。
- Z5 は**チルト**：舞台から上昇しながら視線を上げ、最後に**京都タワーを含む夜景の広がり**と、手前の紅葉の谷を一枚に収める。
- 経路は折れ線（四条大橋→四条通東→八坂神社→ねねの道→二年坂・三年坂→清水寺）。折れ曲がりは通りの交差・境内の入口で行い、ブロック（町家の列）を横切らない。

### フィナーレの見せ方の考え方
- **「登って、開ける」**: 狭く暗い坂から、舞台で一気に視界が開く。**速度を落としながら高度を稼ぐ**（仙台・東京と同じ）。
- **紅葉の赤と夜景の暖色の灯り、空の濃紺**の三層で、色が一つの流れになる。
- **霞**: 盆地の夜景は薄い霞をまとわせる（§10）。京都タワーは霞に埋もれない程度に弱める。
- ビネットは東京の既定を初期値とする。

## 10. 霞・グレーディングの流用方針
- 仕組みは共通側（`haze.js` / `grade.js`）をそのまま使う。霞色は空の地平線色に自動で追従する。
- 京都固有の上書き（`tuning`）が必要。理由：(1) 盆地の晩秋の夕方は薄い霞がかかり、遠景の山並みが段階的に青く沈む（札幌より強め、東京より強め）。(2) 夜の暖色（提灯・紅葉のライトアップ）が主役で白飛びしやすい。(3) 日没後の青い影＋暖色の光の対比を保つ。
- **仮置き（実装後に東京と同じ手順で決める）**:
  - `haze: { start: 500, end: 6000, strength: 0.55 }`（東京より近く・強く、仙台より弱い）。`mountain` は 0.6 から開始（東山の山並みが空に溶ける表現）。
  - `grade: { expDay: 1.06, expDusk: 0.92, highDusk: [1.06, 1.0, 0.92] }`（夕〜夜で暖色のハイライトを残す。紅葉の赤の彩度が落ちないよう、全体の彩度は 1.0 以上）。
  - ビネット 0.22 から開始。
- きらめき・散り葉・提灯の光点は共通の霞の対象外。実装時に東京と同様に、光点・粒子シェーダに霞と同等のコードを京都モジュール内に持たせる（共通は不変）。
- 検証手順は札幌・仙台・東京と同じ（弱・中・強の候補撮影、白飛ばし・黒潰れの画素統計、近景の無変化の証明）。

## 12. 決定事項リスト（オーナーの判断が必要）
各項目の（推奨）が私の暫定案。

| # | 論点 | 選択肢・推奨案 |
|---|---|---|
| U-1 | 時間帯の幅 | **日没の約 15 分前 → ほぼ夜（推奨）**／もっと明るい夕方から始める／完全な夜から始める。「灯りがともる過程」をどこまで見せるか |
| U-2 | 季節 | **晩秋（紅葉ライトアップ）（推奨）**／春（桜・東山花灯路。期間未確認、札幌の夕景とピンクが被る）／夏（祇園祭・仙台と被る）／冬（雪の京都。札幌・東京と被る） |
| U-3 | ルートの最終決定 | **A 案 鴨川→祇園→東山→清水寺（推奨）**／B 案 京都駅→烏丸→四条／C 案 嵐山（別の機会へ）／D 案 伏見稲荷／他 |
| U-4 | 進行方向と圧縮 | **東向きに進み、標高を実際より強調（推奨）**／平坦に近い実寸／四条通を短くして坂に尺を割く |
| U-5 | フィナーレの遠景 | **舞台の高さから市街の夜景＋京都タワーを遠景に小さく（推奨）**／京都タワーを入れない（地図確認で方位が合わない場合）／京都駅ビルも入れる |
| U-6 | 清水寺の扱い | **舞台・本堂・三重塔・仁王門を詳細に作る（推奨。公共性の高い建築の形状再現）**／舞台のみ詳細で他は簡易／境内に入らず外観のみ |
| U-7 | 看板・店舗・実在の施設の表現 | 実在の企業ロゴ・店名・商標は使わず、無地の発光パネル・抽象的な看板にする（推奨。仙台・東京 U-7 と同じ）。**社寺・歴史的建築の形状再現は可**（ロゴ・商標・実在のライトアップ演出の再現はしない）でよいか |
| U-8 | 人出・交通の密度と服装 | **歩行者 1,200・車 300（推奨。秋の混雑を反映、東山の坂は車なし）**／人出を増やす／ほぼ無人。**着物の人を少数の色差しとして混ぜるか**（推奨：混ぜない。舞妓・芸妓の人物は作らない。入れる場合は一般の着物の観光客のみ） |
| U-9 | キャプション文言 | §7 の案で良いか（「京の夜景」か「夜景」か、「東山」か「清水坂」か、最終の見出し、英文表記） |
| U-10 | 動画版の京都ショット | 動画版（`index.html`）も同時に作るか、スクロール版のみ先行するか（**推奨：スクロール版のみ。動画版は触れない**。仙台・東京と同じ扱い） |
| U-11 | 共有コードの扱い | 共通 lib を京都のために拡張せず、**ラップ／コピーして共有側は不変（推奨）**。足りなければ実装前に報告して止まる |
| U-12 | 地理の精度 | **着手前に地図で、四条大橋〜八坂神社〜二年坂・三年坂〜清水寺の長さ・向き・標高差、清水の舞台の向きと京都タワーの方位・距離を確認して数値を直す（推奨）**／概略（記憶ベース）のまま進める。圧縮率もここで確定 |
| U-13 | 天候・空 | **快晴の晩秋の夕方（推奨）**／薄曇り・夕霧（盆地らしさは増すが夜景が弱まる）／雨上がり（石畳の濡れ） |
| U-14 | 路面の表現 | **乾いた石畳＋灯りの光だまり（推奨）**／濡れた石畳（鏡面の疑似表現。負荷と制作量が増える。紅葉の晩秋の乾いた空気とは逆） |
| U-15 | 京都タワーのライトアップの色 | **白〜淡い暖色（推奨）**／季節の特別色（実在の演出は再現しない前提で自由な色） |

| U-17 | 性能の使い方 | **見積もりに余裕があるので、密度を上げず光点と近景の品質に回す（推奨）**／町家・紅葉の密度を上げる（三角形を 130 万程度まで使う） |
