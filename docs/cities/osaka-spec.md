## 1. コンセプト
**真夜中の光、色の変化、商都の熱。** 東京が「ブルーアワー→夜・シャンパンゴールド一色」なら、大阪は**最初から夜**。梅田の高層群と梅田スカイビルの輪郭から入り、中之島の川面を渡り、**御堂筋のイルミネーションのトンネル**を南下する。御堂筋の光は区間ごとに色が変わる（北の暖白→青→ピンク→難波の金）。道頓堀のネオンの色面と川面のグローで熱が最大になり、最後は上昇して通天閣をかすめ、**あべのハルカス（300 m）を見上げる**。

### 既存都市との対比
| | 札幌 | 仙台 | 東京 | **大阪** |
|---|---|---|---|---|
| 季節・気配 | 冬、静けさ、雪 | 盛夏、祭り | 冬の夜、光の密度 | **冬の夜、商都の熱** |
| 時間 | 昼 → 夕 | 夕方 → 夜 | ブルーアワー → 夜 | **夜 → 深夜（最初から暗い）** |
| 色 | 白・青灰 | 緑・五色 | 紺とシャンパンゴールド一色 | **深い藍の空、区間で変わるイルミの色、ネオンの多色** |
| 動く要素 | 雪 | 吹き流し | きらめき＋光跡 | **きらめき＋光跡＋川面のグロー** |
| フィナーレ | テレビ塔→手稲山 | 青葉城址から俯瞰 | 東京タワー | **あべのハルカスを見上げる** |

## 3. 決定事項（本書で確定として記録）
| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| D-1 | 時間帯 | **開始から夜**（夜の早い時間→深夜へわずかに深まる） | 東京（夕→夜）・仙台（夕方）と差別化。大阪の主題は「夜そのもの」 |
| D-2 | ルート | 北→南（梅田→中之島→御堂筋→道頓堀→新世界→あべのハルカス）。フィナーレはハルカス | オーナー提示の推奨設計どおり |
| D-3 | イルミネーションの色 | **区間ごとに変える**：梅田〜中之島＝暖白、中之島〜本町＝青、本町〜心斎橋＝ピンク、心斎橋〜難波＝金 | 実物の御堂筋イルミネーションの色分けの考え方に倣う。東京の金一色との対比 |
| D-4 | 看板・商標 | 実在のロゴ・店名・商標は**使わない**。道頓堀の看板は抽象的な発光色面で表現 | 仙台・東京と同じ方針（グリコサイン等の固有看板も再現しない） |
| D-5 | 雪 | 降らせない | 東京と同じ（冬の乾いた夜）。環境の動きは きらめき＋光跡＋水面グロー |
| D-6 | 人出・交通 | 歩行者 約 1,000・車 約 500（道頓堀・難波は人出多め） | 札幌・仙台・東京と同等の密度 |
| D-7 | 動画版 | 触れない（スクロール版のみ） | 東京 U-10 と同じ扱い |
| D-8 | 共有コード | **wrap-only**：共通 lib・共通側・他都市は変更しない。大阪の差分はモジュール内で完結 | 契約どおり |
| D-9 | ベースシーンの置き場 | 札幌方式の階層：`src/scenes/osaka.js` に `OsakaScene`（CityScene 継承）、スクロール版は `src/scroll/cities/osaka/scene.js` のサブクラスで PathRig・タイル・霞を足す。部品（ground/trees/…）は東京方式でモジュール内に置く | タスク指定。動画版 main.js には登録しない（D-7） |
| D-10 | metadata/cities.json | **変更しない**。osaka のエントリは既存（displayOrder 8、status planned＝動画版の状態） | スクロール版の並びは displayOrder 順で決まるため、京都（7）の次＝実装都市として 5 番目に並ぶ。カード番号はシリーズ通し番号「08」を表示する（既存 3 都市も 01/02/03 でシリーズ番号と一致）。displayOrder を詰めると動画版の 10 都市計画（横浜 4・金沢 5・名古屋 6）と衝突する |
| D-11 | カード CSS | `styles-scroll.css` に `.c-osaka::before` の新規ルール**のみ**追加（既存ルールは不変） | 東京カードのグラデーション承認（2026-11-23）と同種の、新規都市専用ルール |
| D-12 | 回帰テスト | `tools/test-collection.mjs` を 4 都市に拡張（東京 Step 7 で 3 都市化した前例に倣う）。カード 4 枚、フィナーレの連鎖に大阪を追加し、大阪のフィナーレを締め表示にする | テスト自体が都市数を前提に書かれているため |
| D-13 | 霞・グレーディング | 初期値は東京の考え方（霞は弱く遠く、露出は夜側）。`tuning` で haze { start 700, end 8000, strength 0.5 }、grade { expDusk 0.92 } から始め、撮影で確定する | 大阪は東京より一段深い夜。ネオンの白飛びを抑える |
| D-14 | 地理 | 記憶ベースの概略＋圧縮。数値は `osaka-layout.md` と `layout.js` に集約し、後から直せる形にする | 東京 Step 0 と同じ扱い（このセッションは地図へ直接アクセスできない） |

## 4. プロシージャル要素（方針）
- 共通 lib（createSky、BuildingBatch＋ファサード、createGlowPoints、createCars、createPedestrians、タイル分割、霞）を**変更せず**使う。
- 建物：梅田は 100〜200 m 級、中之島は低層（20〜60 m）、御堂筋沿いは 60〜140 m の壁、難波・新世界は低〜中層の密集、天王寺は中層。
- 街路樹：冬のイチョウの裸木（御堂筋・中之島）。枝に LED の光点を巻き、**点ごとに色**を持たせる（D-3 の色分け）。近景／遠景 LOD は東京の trees 方式。
- 水面：堂島川・土佐堀川・道頓堀川。実反射は使わず、暗い水面＋岸の灯りの反転グロー帯（道頓堀は多色のグロー）。
- ランドマーク：
  - **梅田スカイビル**：2 棟の板状タワー＋頂部のリング（空中庭園）。ファサードのバッチに 2 棟を入れ、リングは専用ジオメトリ＋光点の輪。
  - **大阪駅**：大屋根の量塊（抽象化した大屋根＋ガラス面の帯）。
  - **中之島の公会堂**：低層のレンガ量塊＋小さなドーム（形状の示唆のみ）。
  - **通天閣**：格子の塔（梁の生成、108 m）。頂部と稜線に光点。
  - **あべのハルカス**：300 m。段々に細くなる 3 段のガラス棟（バッチの kind=2）＋稜線・頂部の光点。
  - **環状線の高架**：難波→天王寺の斜線に高架と電車の光の帯（フィナーレの前景）。
- 遠景：街区の簡略箱＋窓明かりの海（東京 far 方式）。東〜南東に生駒山系の稜線シルエットを薄く。

## 6. カメラ方針
- 共通：7 秒、p=0.94 で尺が終わり以降は最終構図を保持。横は進行度キー（kt(p) の warp）、縦は PathRig（通りの中心線の折れ線ドリー）。near は 4 m のため、枝・建物へ 4 m 未満に近づかない。
- 横画面：A は梅田スカイビルを画面に収める高所から。B は川を渡る低い俯瞰。C は御堂筋の中心軸・高さ 5〜8 m のトンネル。D は道頓堀の水面と色面を見渡す。E は上昇しながら南東へ旋回し、通天閣を前景にハルカスを見上げる。
- 縦画面：駅前→御堂筋の中心線→道頓堀橋→新世界の通り→天王寺へ折れる折れ線。フィナーレはチルトアップでハルカスを縦に収める。

## 7. 性能予算（絶対条件：iPhone で滑らかに動くこと）
- 三角形：最大で約 60 万を目標（上限 180 万）。描画コール 250 以内。光点は約 10 万（東京と同程度）を目安に、画面内 200k 以下。
- 動く CPU 更新（車・歩行者）は東京と同等まで。
- 検証：全 p の縦横撮影、renderer.info、`?tiles=0` との画素差分 0、既存 3 都市の画素差分 0（変更前後）。**実機 FPS・発熱・メモリは未検証扱い**（ソフトウェア描画の数値は報告しない）。
